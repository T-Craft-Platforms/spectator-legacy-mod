# Spectator Legacy Mod

Install the jar on both the Minecraft 1.6.4 Forge client and server. With cheats or operator permission, use `/gamemode spectator` or `/gamemode 3` to enter spectator, and `/gamemode` with another mode to leave it. Press F3+N to toggle between spectator and the previous game mode. The standard `/gamemode` player argument also works.

While spectating, move in flight and scroll to change flying speed. Double-tap forward to sprint with a flight boost. Left-click an entity to follow its view; use F5 to change perspective and press the sneak key to return to free flight. Press a number key to open the player selection bar, then press 1–9 to teleport to a listed player. The bar shows the heads of up to nine players currently loaded in your dimension. The regular hotbar and status bars are hidden. Right-click vanilla inventory blocks, horses, donkeys, mules, chest minecarts or hopper minecarts to view a read-only snapshot without opening the actual container. Chests, furnaces, dispensers, droppers, hoppers, brewing stands, beacons and these entities use their usual layouts. Snapshots are not live, show at most 54 slots, and do not support custom mod inventories. Inventory and container slots are read-only while spectating. Vertical flight also follows the selected speed. Spectators appear as translucent heads, including in the inventory preview.

The mod bypasses the server's collision checks for spectator movement, prevents spectators from triggering pressure plates and tripwire, and suppresses player-generated vanilla particles and the client block overlay. The implementation uses a Forge core plugin and may conflict with other mods that modify the same methods. Camera behavior and rendering have not yet been verified in an interactive Minecraft client. Later Minecraft versions' entity-specific spectator shaders are not available in 1.6.4.

## Minecraft versions

Minecraft 1.6.2, the 1.6.3 pre-release, and 1.6.4 have experimental builds; each has started in a Forge client and dedicated server. The 1.6.3 server needs a LaunchWrapper workaround documented in the compatibility guide. Gameplay and multiplayer testing remains outstanding. Minecraft 1.6.1 has a Forge distribution, but its GUI, mouse, and rendering APIs differ and the port is not yet buildable. See `versions.json` and the compatibility guide for the exact targets and status. Use only the jar built for your Minecraft version.

## Build and test

Install [mise](https://mise.jdx.dev/) and Python 3, then run `mise install`, `mise run setup -- 1.6.2`, and `mise run build -- 1.6.2` (replace the version with a buildable target). Jars are in `build/<minecraft-version>/libs`. Java 8 is required. The 1.6.4 build uses Gradle 3; the older targets use a pinned Gradle 7.6.4 wrapper and Voldeloom. Recent IntelliJ versions do not support importing Gradle 3; use the terminal build.

Install Prism Launcher, enable its automatic Mojang Java downloads, and sign in to a Minecraft account. `mise run prism -- 1.6.4` builds the jar, creates or updates a dedicated `spectatorlegacy-1.6.4` instance with the selected Forge version, and launches it using Prism's automatic Java selection. `mise run prism:prepare -- 1.6.4` prepares the instance without launching. Existing worlds and unrelated mods in the managed instance are preserved. The task refuses to modify an existing instance with the same name unless it created it. On systems where Prism cannot be found, set `PRISM_LAUNCHER` to the executable; set `PRISM_DATA_DIR` to use a non-default Prism data directory. Prism may prompt for login or downloads on first launch.

Prism can cache instance settings while it is open. Close it before running the task if it does not pick up a newly created or changed instance configuration. For legacy certificate compatibility the managed instance includes the per-instance Java security settings described in Prism's [troubleshooting guide](https://prismlauncher.org/wiki/overview/troubleshooting/#very-old-forge-modpacks-with-modern-java-8-runtimes). Existing custom JVM arguments and security files are preserved; if custom arguments are present, add `-Djava.security.properties=java.security` yourself if needed.

The game-independent rules are in `common/`; Forge-dependent behavior lives in `implementations/`, and `targets/` contains each target's build and entry points. The target inventory explicitly selects implementation providers and toolchains. CI builds every buildable target; a version tag creates a draft release only when at least one target is marked release-ready. See [the compatibility and composition guide](docs/compatibility.md) for current status and release checks. Run `mise run build -- 1.6.4` for a specific target and `python -m unittest discover -s scripts/tests -v` for composition tests.
